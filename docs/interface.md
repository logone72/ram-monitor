# 화면·설정 사양

## 메인 화면

단일 창, 단일 화면이다. 기본 크기는 `1000 × 680pt`, 최소 크기는 `820 × 520pt`로 둔다.

```text
┌─────────────────────────────────────────────────────────────┐
│ RAM Monitor                                      Search     │
├──────────────────────┬──────────────────────────────────────┤
│                      │ Work unit          RAM          CPU  │
│   230pt pie chart    │ ▸ Google Chrome   3.2 GB      18%  │
│                      │ ▸ Xcode            2.1 GB       9%  │
│   top 8 legend       │ ▾ RAM Monitor      82 MB       1%  │
│                      │    RAMMonitor       80 MB       1%  │
│   total / mode       │    helper            2 MB       0%  │
└──────────────────────┴──────────────────────────────────────┘
```

- 좌측 36%: 지름 약 `230pt`의 RAM 파이 차트와 범례
- 우측 64%: 하나로 통합한 작업 그룹 목록
- 창이 좁아져도 차트 영역은 최소 `300pt`를 유지한다.
- 창 높이가 작으면 차트 영역을 독립적으로 스크롤한다. 파이 지름을 줄이지 않고 범례와 물리 RAM 요약까지 접근할 수 있어야 한다.

## 파이 차트

- Swift Charts의 `SectorMark`를 사용한다.
- 그룹 색상은 표시 순위가 유지되는 동안 안정적으로 유지한다.
- 범례는 상위 8개 작업과 `Other`를 원본 측정값 그대로 표시한다.
- 상단에는 현재 측정 모드, 중앙에는 `Measured process total`과 해당 모드의 측정 합계를 표시한다.
- 물리 RAM 용량은 차트 분모와 분리해 하단 `Physical RAM` 요약에 표시한다.
- 백분율은 물리 RAM 사용률이 아닌 측정된 프로세스 메모리 안에서의 비중임을 안내한다.
- 조각이나 범례에 마우스를 올리면 해당 조각을 강조하고 중앙에 이름·바이트·백분율을 표시한다. 강조는 짧게 전환하며 macOS의 동작 줄이기 설정에서는 애니메이션을 생략한다.
- 목록에서 그룹이나 subprocess를 선택하면 이전 호버를 해제하고 부모 그룹에 해당하는 조각을 강조한다. 호버는 목록 선택을 바꾸지 않으며, 마우스가 벗어나면 기존 선택 강조로 돌아간다.
- 그룹 조각이나 범례를 클릭하면 해당 부모 행을 선택하고 스크롤해 표시한 뒤 목록에 키보드 포커스를 준다. 검색에 가려진 대상은 검색을 해제해 표시한다.
- 선택된 그룹의 조각·범례·목록 행을 다시 클릭하면 선택과 강조를 해제한다. 차트 중앙이나 빈 영역, 정렬·펼치기 버튼 등 선택을 유발하지 않는 요소를 클릭하거나 검색창을 활성화해도 해제하고 중앙에 측정 프로세스 합계를 표시한다. 해제한 항목에 포인터가 남아 있는 동안은 다시 강조하지 않으며, 벗어났다가 돌아오면 호버가 다시 동작한다.
- `Other`에 포함된 그룹을 목록에서 선택하면 `Other`를 강조한다. `Other` 자체를 클릭하면 특정 그룹을 임의 선택하지 않고 기존 선택·강조를 해제한다. 측정 불가·0인 그룹은 강조할 조각이 없다.
- 선택은 그룹 ID로 유지한다. 주기적 갱신·모드 전환으로 다른 동명 그룹이 선택되지 않으며, 선택 그룹이 사라지면 선택을 해제한다. 정렬 버튼 클릭은 선택을 해제하지만 키보드 방향키로 그룹을 펼치거나 접을 때는 선택을 유지한다.
- 색만으로 구분하지 않고 모든 조각에 텍스트 범례와 접근성 라벨을 제공한다.

## 작업 목록

항상 표시하는 열:

- Work unit
- RAM
- CPU

설정으로 표시하는 열:

- Threads: 기본 켜짐
- PID: 기본 꺼짐
- Processes: 기본 꺼짐
- Architecture: 기본 꺼짐

기본 정렬은 RAM 내림차순이다. 열 머리글을 누르면 RAM, CPU, 이름, Processes 기준으로 정렬하고 같은 머리글을 다시 누르면 방향을 바꾼다.

그룹 행의 disclosure 버튼을 누르면 subprocess가 같은 열 구조로 펼쳐진다. subprocess에도 선택한 RAM 모드가 그대로 적용된다.

헤더와 행은 같은 `ScrollView`의 `LazyVStack`에 배치하고, `Section` 헤더를 상단에 고정한다. 스크롤바가 항상 표시되거나 자동으로 숨겨져도 같은 가용 너비를 사용해 열의 오른쪽 끝이 일치해야 한다. 스크롤바 폭을 고정 padding으로 보정하지 않는다.

검색은 그룹 이름과 subprocess 이름을 실시간으로 필터링한다. 검색 결과에 포함된 subprocess가 있으면 부모 그룹도 남긴다.

## 설정

### General

| 키 | 선택지 | 기본값 |
|---|---|---|
| `memoryMetric` | Physical Footprint / Resident Size | `physicalFootprint` |
| `refreshInterval` | 1 / 2 / 3 / 5 / 10초 | `2` |
| `numberFormat` | Decimal / Binary | `decimal` |
| `defaultSortOrder` | RAM / CPU / Name | `memory` |
| `launchAtLogin` | 켜짐 / 꺼짐 | `false` |

### Columns

| 키 | 기본값 |
|---|---|
| `showThreadsColumn` | `true` |
| `showPIDColumn` | `false` |
| `showProcessCountColumn` | `false` |
| `showArchitectureColumn` | `false` |

CPU와 RAM 열은 끌 수 없다. 설정은 `UserDefaults`에 저장하고 로그인 시 실행은 `SMAppService.mainApp`으로 등록한다.

## 상태와 오류 표시

- 첫 샘플: RAM은 즉시 표시하고 CPU는 `—`로 표시한다.
- 일부 프로세스 접근 실패: 해당 값만 `—`로 표시한다.
- 모든 프로세스 열거 실패: 기존 목록을 지우지 않고 상단에 `Unable to refresh processes`를 표시한다.
- 검색 결과 없음: `No matching work units`를 표시한다.
- 로그인 시 실행 등록 실패: 토글을 원래 값으로 되돌리고 설정 화면에 오류를 표시한다.
- 데이터가 오래됨: 두 번 연속 갱신 실패 시 마지막 성공 시각을 표시한다.

## 기본 상호작용

- `⌘F`: 검색
- `⌘,`: 설정
- 위·아래 화살표: 그룹 선택 이동
- 왼쪽·오른쪽 화살표: 그룹 접기·펼치기
- VoiceOver 읽기 순서: 그룹명 → RAM → CPU → 선택 열 → subprocess 수
